### Acceptance Checklist
- A Review + Iteration Desk v0 can be invoked with repo owner/name, PR number, and associated Notion task/work-order identifier.
- The desk collects and normalizes PR metadata, PR body, changed files, diff summary, CI/check status, GitHub-exposed Vercel/deployment evidence when available, Notion task/work-order content, acceptance checklist, and available work-order evidence.
- The desk produces a typed review packet with one of exactly three verdicts: Needs Codex Fixes, Ready for Human Smoke Test, or Blocked.
- Deterministic gates override model output for hard blockers such as missing/unreadable PR, missing/unreadable Notion work order, missing diff evidence, invalid Claude output, or failed required checks.
- Claude review is structured, schema-validated, and explicitly evaluates implementation evidence against acceptance criteria, changed files, known fragile flows, and do-not-break flows.
- If verdict is Needs Codex Fixes, the desk generates a focused draft Codex fix brief with affected files/areas, failing evidence, required fixes, and verification steps.
- If verdict is Ready for Human Smoke Test, the desk escalates to Sherif for final smoke testing/approval rather than claiming merge readiness.
- If verdict is Blocked, the desk lists missing credentials, unavailable systems, or missing evidence needed to proceed.
- Review result writeback to Notion records verdict, review summary, risks, missing evidence, suggested smoke tests, and draft fix brief if present without marking final approval.
- Vercel green / deployment success alone is not treated as sufficient proof of product correctness; PR #6-style case should remain Needs Codex Fixes or Ready for Human Smoke Test only when acceptance evidence supports it.
- Unit tests cover verdict policy, schema validation, invalid Claude output handling, missing evidence, failed checks, and a PR #6-style green-preview-but-insufficient-evidence scenario.
- No product runtime flows in SherifHaidar/personal-chief-of-staff are changed as part of this implementation unless Sherif explicitly redirects the task.
